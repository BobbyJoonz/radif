## ۱. این چیست

فروشندهٔ اینستاگرامی کارش را در دایرکت انجام می‌دهد، ولی اطلاعات خرید در همان متن پراکنده است: «واریز کردم»، «آدرسم عوض شده»، «کد رهگیری کو؟». ردیف این مسیر را می‌سازد:

> **پیام می‌رسد ← نوع درخواست و فیلدها با شاهد پیشنهاد می‌شود ← شما تأیید یا اصلاح می‌کنید ← کار بعدی و پاسخ از وضعیت ثبت‌شده ساخته می‌شود.**

قاعدهٔ اصلی محصول: **ادعای مشتری با واقعیت تأییدشده قاطی نمی‌شود.** «واریز کردم» یک ادعاست؛ تأیید پرداخت کار یک انسان با نقش مالک است.

## ۳. شروع سریع

```bash
pnpm install          # کلاینت Prisma هم ساخته می‌شود
pnpm db:init          # پستگرس پرتابل + دیتابیس‌ها (یا: docker compose up -d)
pnpm db:deploy        # مایگریشن‌ها
pnpm db:seed          # دموی کامل
pnpm dev              # http://localhost:3000
pnpm worker           # ترمینال دوم: صف را پردازش می‌کند
```

اگر پستگرس آماده داری، فقط `DATABASE_URL` را در `.env` بگذار (نمونه: `.env.example`).

## ۴. ورود به دمو و ثبت‌نام

سه راه، هر سه واقعی:

| راه | از کجا | نتیجه |
|---|---|---|
| **بدون ثبت‌نام** | دکمهٔ «بدون ثبت‌نام امتحان کن» | حساب دموی **تصادفی** از `/api/guest`، ورود واقعی، صف باز می‌شود |
| **ثبت‌نام** | `/{fa\|en}/signup` | حساب واقعی + ساخت فروشگاه و نقش مالک |
| **ورود** | `/{fa\|en}/login` | حساب‌های دموی آماده |

| ایمیل | نقش | فروشگاه |
|---|---|---|
| `maryam@toranj.demo` | مالک | آتلیهٔ ترنج |
| `saeed@toranj.demo` | اپراتور | آتلیهٔ ترنج |
| `raha@raha.demo` | مالک | کفش‌خانهٔ رها |

گذرواژهٔ همه: `radif-demo-1405`

**نقش‌ها سمت سرور اعمال می‌شوند:** تأیید پرداخت و تنظیمات فقط مالک؛ اپراتور در سرویس ۴۰۳ می‌گیرد، نه این‌که فقط دکمه‌اش پنهان شود.

## ۵. معماری

```
مرورگر
  ├─ صفحه‌های عمومی   →  src/app/[locale]/         لندینگ · ورود · ثبت‌نام
  ├─ صفحه‌های محصول  →  src/app/[locale]/(app)/    با سشن
  └─ تغییرات         →  /api/*  →  سرویس‌ها

سرویس‌ها  src/server/services/*   فقط از session؛ tenant از client گرفته نمی‌شود
قواعد     src/server/domain/*     بدون I/O، آزمون‌پذیر
مدل‌ها    src/server/providers/*  mock + seam ارائه‌دهنده واقعی
ورودی     src/server/channels/*   فایل · بازپخش · (بعداً) اینستاگرام
صف        src/server/worker/*     SKIP LOCKED + lease + backoff
داده      Prisma 7 + PostgreSQL 17
```

**مرزهای مهم:** شناسهٔ فروشگاه دیگر ۴۰۴ می‌گیرد نه ۴۰۳ (تا قابل کاوش نباشد)؛ پیشنهاد هرگز روی تصمیم انسانی نمی‌نویسد؛ تأیید پیش‌نویس به پرداخت و ارسال دست نمی‌زند.

## ۸. متغیرهای محیطی

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `DATABASE_URL` | — | رشتهٔ اتصال پستگرس |
| `BETTER_AUTH_SECRET` | — | در تولید الزامی؛ در دمو از `DATABASE_URL` مشتق می‌شود |
| `BETTER_AUTH_URL` | خودکار از Vercel | آدرس عمومی |
| `APP_MODE` | `demo` | `production` دمو/seed/reset را می‌بندد |
| `INGESTION_MODE` | `replay` | `file` · `live` |
| `DECISION_PROVIDER` | `mock` | یا `typesafe` + `TYPESAFE_API_KEY` |
| `OUTBOUND_MODE` | `preview` | ارسال واقعی هرگز خودکار نیست |
| `CHANNEL_TOKEN_ENC_KEY` | — | کلید AES برای توکن کانال |

## ۹. آزمون و کیفیت

```bash
pnpm typecheck && pnpm lint && pnpm test
```

- آزمون‌ها روی **PostgreSQL واقعی** اجرا می‌شوند، نه mock.
- پوشش قواعد ریسک: وبهوک تکراری، پرداخت تأییدنشده، تأیید پیش‌نویس بدون تغییر پرداخت، چند نیت در یک پیام، دو سفارش باز، کد رهگیری ساختگی، مبلغ بی‌واحد، تغییر آدرس پس از ارسال، شناسهٔ فروشگاه دیگر، نبود اجازهٔ اپراتور، تزریق دستور در پیام، timeout ارائه‌دهنده، ری‌استارت worker، ویرایش هم‌زمان.
- اسکن طراحی: `pnpm design:shots` (۱۴۴۰/۷۶۸/۳۹۰ + اسکن خودکار).

## ۱۰. استقرار

```bash
# Vercel → Project Settings → Environment Variables
DATABASE_URL=…   BETTER_AUTH_SECRET=…   BETTER_AUTH_URL=https://…

# یک‌بار روی همان دیتابیس
npx prisma migrate deploy
npx prisma db seed
```

اگر ابزار محلی نداری، از داخل خودِ سایت:

| مسیر | کار |
|---|---|
| `/api/setup` | ساخت جدول‌ها + دمو |
| `/api/setup?enrich=1` | ارتقا/ترمیم دموی موجود |
| `/api/health?deep=1` | تشخیص: دیتابیس، schema، منبع سکرت، کامیت فعال |

**محدودیت صادقانه:** worker روی Vercel اجرا نمی‌شود؛ پیام‌ها ذخیره و صف می‌شوند ولی تحلیل تا اجرای worker روی یک هاست دیگر انجام نمی‌شود.
